Here are the steps to make the PMM bitmap dynamically allocated, and (for completeness) what would be required to make the kernel image itself “dynamically allocated” (though this is not standard or practical):

1. Dynamically Allocating the PMM Bitmap:
   - Change the bitmap from a static array to a pointer: `static uint8_t *bitmap;`
   - Parse the Multiboot2 memory map to find the highest usable RAM address and total RAM size.
   - Calculate the required bitmap size: `bitmap_size = (frame_count / 8);`
   - Find a free region in RAM large enough for the bitmap (not overlapping kernel, boot info, etc.).
   - Set `bitmap = (uint8_t *)<chosen address>;` and initialize it with `memset`.
   - Mark the frames used by the bitmap itself as reserved in the PMM.

2. Dynamically Allocating the Kernel Image (not standard):
   - The kernel image must be loaded by the bootloader at a fixed address, so you cannot allocate it dynamically at runtime.
   - If you want a relocatable kernel, you can use position-independent code and have the bootloader load the kernel at any address, but this is advanced and requires special linker and bootloader support.
   - The kernel’s code, data, and initial stack must always be loaded before the kernel runs.

Summary:
- Only the PMM bitmap and other runtime data structures can be dynamically allocated after boot.
- The kernel image itself must be loaded statically by the bootloader.
