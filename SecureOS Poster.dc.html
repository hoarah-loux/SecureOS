SecureOS

An operating system written from scratch, with security as a first-order design constraint rather than a layer added on top.

01

Overview

SecureOS is a 64-bit x86 operating system written from scratch; about 35,000 lines of C and assembly, not counting the vendored newlib and doom sources. GRUB loads it as a Multiboot2 kernel; from there it brings up long mode, its own four-level page tables, interrupts and a framebuffer console, then runs unprivileged ELF programs on top of a physical and virtual memory manager, a preemptive scheduler, a FAT32 driver over real IDE block I/O, and a 21-call system call interface.

It boots to a shell today on QEMU, from both BIOS and UEFI images, loads binaries off the FAT32 volume and runs them under timer preemption. The heaviest demonstration is doom: ported through a retargeted newlib, it plays at 320×200 over the same syscall surface every other program uses.

02

Problem & motivation

The hardware already offers the isolation primitives — privilege rings, per-process address spaces, no-execute and user/supervisor page bits. General-purpose kernels dilute them behind millions of lines of trusted code, where a single missing check is unauditable in practice. Building the kernel from nothing makes every enforcement point explicit and small enough to read.

The goal: a process touches only memory it was granted, on the terms it was granted — and a fault in userland kills that process, never the kernel.
